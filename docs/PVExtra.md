# Компонент на основе PVExtra
Компонент на основе PVExtra создает в MODX:
1. Ресурсы (страницы). Настройки в файле _build\configs\resources.js. Формат бывает плоский (ключ = контекст) и **по сайтам** (ключ = список идентификаторов сайта через запятую, значение — обычная структура; `'*'` — для остальных сайтов). Сайт опознаётся по метке из системной настройки `gtsapi_site_key` (рекомендуется — не раскрывает адреса в публичном коде), по хосту или по хешу хоста (`sha1:…`). Второй нужен, когда на разных сайтах разные родители и шаблоны: внутри блока их пишут прямо числом/именем. Родителя можно не зашивать и в плоском формате — ключи `parent_setting` / `parent_alias` / `template_setting`. Подробности и защита от чужого алиаса — в комментарии внутри файла.
2. Конфиг таблиц базы в _build\configs\gtsapipackages.js. Описание в docs/use_gtsapipackages.md.
3. Начальные данные в базу в файле _build\configs\data.js. Формат тоже бывает плоский (ключ = пакет) и **по сайтам** (ключ = метка сайта из `gtsapi_site_key`, хост или `sha1:…`; `'*'` — для остальных). Второй нужен, когда справочные строки осмысленны только на своих инсталляциях, а пакет выкладывается публично: на чужом сайте блока нет — данные просто не ставятся. Формат определяется по структуре, старые data.js работают без правок.
3.1. Зависимости пакета в файле _build\configs\dependencies.js — ключ = имя пакета, значение `{version, service_url, url, required}`. Резолвер ставится **первым** и доустанавливает недостающее: ищет у провайдера (`service_url`) либо качает по прямой ссылке (`url`, для пакетов вне репозиториев). Уже стоит нужная версия или новее — пропускает. `required: true` (по умолчанию) и поставить не вышло — установка прерывается с сообщением, что доставить руками.
4. Схему базы компонента в файле core\components\[package]\model\schema\[package].mysql.schema.xml.
5. Сервисный класс компонента в файле core\components\[package]\model\[package].class.php.
6. Если нужна сложная форма или внешние действия читай docs/pvtables-gtsapi-table-creation.md.
Если это не нужно старайся задавать таблицу в _build\configs\gtsapipackages.js. На странице компонента выводи {'!PVTable' | snippet : ['table'=>'имя таблицы']}
7. Для дополнительного функционала на стороне сервера используем триггеры. docs/gtsAPI_triggers.md.
8. В коде vue используй апи docs\api-usage-guide.md.
9. В коде vue импортируй компоненты primevue из 'pvtables/dist/pvtables'. Например import { PVTables, Button, Dialog } from 'pvtables/dist/pvtables'.
10. Используй PVForm. docs\pvform-usage-guide.md.
11. Права доступа. Не привязывайся к чужим группам пользователей — на другом сайте их нет. Привези СВОИ разрешения MODX в _build\configs\permissions.js (шаблон разрешений + разрешения + готовые политики), а в gtsapipackages.js у таблицы укажи `permissions: 'имя_разрешения'` вместо `groups`. Админ вешает политику на ту группу, которая у него уже есть. Свою группу пользователей заводить только если нужен закрытый раздел «добавь людей» — тогда _build\configs\user_groups.js.
12. ⚠️ Конфиг таблицы в gtsapipackages.js **версионируется**: после любой правки (поля, groups, permissions, actions) инкрементируй `version`, иначе изменения молча не применятся — сборка отрапортует «Пакет установлен», а в БД останется старое.
